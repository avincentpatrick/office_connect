## PITFALLS
- Hard-coding the DOH program tree: it demonstrably changed between the FY 2018 PREXC adoption and FY 2025 (programs split/renamed, e.g., today's 'Health Policy and Systems Strengthening' and 'Local Health System Support' programs). The PAP registry must be per-fiscal-year seed data with an admin maintenance flow, not schema or code constants.
- Storing the PAP or full UACS code as one opaque string: rollups required by BED/BAR/FAR (by cost structure, by program, by subprogram, by allotment class) become fragile; store parsed segments with digit-length check constraints and derive the concatenation.
- Reusing an internal activity ID or PAP mapping for a different activity in a later year â€” violates the UACS never-reuse rule and silently corrupts multi-year accomplishment history; deactivate and create new, exactly like UACS repository behavior.
- Expecting 15-digit PAP codes in the printed GAA: the GAA/Official Gazette volumes show descriptive line items only; the machine codes live in the UACS repository (uacs.gov.ph) and NEP details, so the app needs a UI to attach codes to registry entries rather than a GAA parser.
- Ignoring continuing appropriations: treating only one fiscal year's codes as 'active' breaks Q1â€“Q2 reporting when prior-year and current-year appropriations are both live.
- Classifying property with the obsolete P15,000 threshold â€” since COA Circular 2022-004 the PPE line is P50,000 per individual item; below that is semi-expendable, a different object code and custodian document (ICS not PAR).
- Using the Sector code (instead of the required Sub-sector) or 'Others' placeholder codes for transaction capture â€” both are explicitly prohibited UACS practices.
- Storing 8-digit object codes without the 2-digit sub-object suffix (UACS object codes are 10 digits, e.g., 5-02-01-010-00), which breaks reconciliation with agency accounting exports.
- Assuming the office (a bureau) has its own UACS organization code â€” the org segment bottoms out at the operating unit (DOH Central Office); internal office/division codes are purely local and must never be embedded into the UACS fields.
- Conflating WFP granularity with GAA PAP granularity: GAA activity lines are coarse ('Local Health Systems Development and Assistance'); a WFP has dozens of internal activities mapping many-to-one to a single PAP â€” the registry needs both levels with a rollup relation.
- Missing the variance-justification requirement: BAR No. 1 column 14 requires reasons/justifications for target-vs-accomplishment variances â€” an accomplishment module without a mandatory variance-remarks field cannot produce a compliant BAR 1.
